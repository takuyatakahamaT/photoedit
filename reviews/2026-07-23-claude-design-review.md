# Claude設計前レビュー統合メモ

- 実施日: 2026-07-23
- レビュー方式: Claude Code CLI / Opus / read-only / 設計前
- 対象: `DESIGN.md`
- 理由: プロ用途の色品質、RAW現像、Lightroom XMP近似、17,000枚規模のデータ安全性が高リスクなため

## 主な指摘

- CIRAWFilterだけではAdobe Color、DCP、PV2012の独自処理を再現できず、Lightroom近似が早期に頭打ちになる可能性が高い。
- 色品質のGo/No-GoにΔE、肌色、ハイライト、官能評価の閾値が必要。
- Phase 0をRAW基礎色、XMP、操作性能へ分け、RAW基礎色を先に判定すべき。
- 17,000枚の初回スキャンとファイル指紋コストを実測すべき。
- SSD側だけにカタログを置くと、自動保存とSSD抜去時UXが矛盾する。
- 選別専用モードを早い段階へ入れるべき。

## 採用した判断

- `ImageDecoder`境界を設け、Core Image backendを交換可能にする。
- Phase 0をSpike A/B/Cへ分割し、色差ゲートを追加する。
- 完成版の主カタログはMac側、SSD側はバックアップにする。
- ProcessVersion 11を初期対象として固定する。
- 永続historyを初期版から外し、Undoはセッション内とする。
- 選別専用モードと`P`/`X`/`U`をPhase 1へ移す。
- 部分ハッシュを初期版から外し、大規模走査の実測後に導入する。

## 採用しなかった判断

- ブラシより先にリニア/ラジアルグラデーションを実装する案は見送る。ユーザーが明示した中核要件がブラシであり、色エンジン確定後にベクターストローク方式で実装する。
- Phase 1でHSLを完全に外す案は一部採用。手元XMPの再現に不可欠だが、まず露出とトーンカーブで処理順を固め、HSLはPhase 2へ送る。

## 残存リスク

- Lightroom基準画像がまだないため、現時点で色差ゲートは実行できない。
- DC-S5以外のLumix RW2は未検証。
- Core Imageが基準を満たさない場合、LibRaw + DCP対応は大きな追加実装になる。
