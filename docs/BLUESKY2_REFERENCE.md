# bluesky2を今回の比較写真へ合わせる作業

> 2026-09-22 方針変更: この文書のプリセット専用fitは不採用。新規自動適用を停止し、[汎用XMPエンジン設計](GENERIC_XMP_ENGINE.md)へ移行する。v4局所補正は試作で中止。以下は調査履歴であり、汎用互換の達成を意味しない。

## 目的

オーナーが追加した3組の「RAW・未調整JPEG・Lightroomでbluesky2を適用したJPEG」を基準に、Photo Benchでも同様の明るさと色の仕上がりを得る。今回の対象はbluesky2に限定する。設計・比較・レビューはメイン担当、production実装はオーナー指定のLuna / maxが担当する。

写真の元データは`exports/editing-mvp-20260922/lightroom-reference/`にある。3 RAW、6 JPEG、3 sidecar XMPの12ファイルを確認し、サイズとSHA-256を`.photobench/bluesky2-20260922/inputs.json`へ記録した。全画像は6000×4000、RAWはPanasonic DC-S5。原本とオーナーの参照JPEGは変更しない。

## 参照の意味

未調整JPEGはLightroom書き出しで、単なるカメラ内JPEGではない。RAW経路とJPEG経路の差を区別する。

設定を読めた適用後JPEG2枚には、同梱XMPと異なる露出+0.79、ハイライト−79、シャドウ+46、白レベル−56が記録されている。同梱XMPはそれぞれ+0.42、−59、+20、+6。オーナーから「bluesky2自体を更新した」と回答を得た。目標画像は今回提供された更新版の適用後JPEGとし、更新後XMP `bluesky2-updated.xmp`を受領し、上記4数値と一致することを確認した。SHA-256は`01383daec2d7ba46bc0cf857e597ee85e6fab636c14c01c837fbf350eacbb054`。ライブラリには更新版を追加し、旧XMPと既存編集を維持する。

また、集合写真1枚には粒子と別レンズの補正が記録され、適用前後でAdobe Lookの情報も異なる。残り1枚のJPEGには現像パラメータが含まれていない。3枚のJPEGを同じXMP数値だけによる出力と断定しない。

## 比較方法

1. 既存エンジンのbasic / HSL・カーブありを、RAW / JPEG各3枚で書き出す。
2. 適用後JPEGに記録された共通の4数値を使った場合も比較する。数値を合わせるだけでは、顔や室内の明るさが十分に揃わないことを確認した。
3. デコード直後の色から、全写真で共有する小さな色変換を推定する。推論時に写真名、座標、教師JPEG、個別の調整値は参照しない。
4. RAW / JPEGは入力の現像処理が異なるため、変換を分ける。RAW版はDC-S5限定。
5. 3枚のうち1枚を除いて変換を作り、除いた写真にも適用する比較を3通り行う。これはleave-one-outの診断であり、未閲覧の独立holdoutや他機種への一般化の証明ではない。

数値比較は900×600へ正規化し、対応点から求めたhomography、端部を除外する同じmask、1.2pxのGaussian blurを各候補に共通適用する。レンズ形状や粒子の違いで色の評価が支配されるのを抑えるためである。**製品出力にはこの位置合わせ・ぼかしを入れない。** 原寸の見た目と白飛びも別途確認する。

## 実装方針

参照補正は`niho-bluesky2-reference-20260922-v1`という明示的な版を持つ。既存XMPの一般的な近似計算を、そのままAdobe互換と称するものではない。

- デコード直後のextended-linear sRGBへ、明るさの区分線形曲線と滑らかな色差項による共通変換を適用する。
- 係数は3枚の比較から得た小さな数値配列だけを使用する。写真・教師画像・写真名の判定分岐は製品に入れない。
- 参照補正がプリセット全体の仕上がりを担い、その後に露出・色温度・色かぶり・彩度等の追加調整を行う。
- 補正のIDを編集設定へ保存し、再起動・Undo・プレビュー・JPEGで同じ処理を使う。過去の保存データには新しい補正を自動で追加しない。
- 他のプリセットと未補正画像の経路を維持する。既存の最終sRGB変換と縮小順序も維持する。

## 証跡と進捗

private作業記録は`.photobench/bluesky2-20260922/`、比較出力は`exports/bluesky2-20260922/`。

## オーナーによる色の確認（継続中）

2026-09-22、v1比較を見たオーナーから「よくなってきてるけどまだあと少し。特に発色・彩度はLightroomの方が良い」とフィードバックを受けた。**v1は画質受け入れ済みとはしない。**

彩度スライダーを一律+15 / +30にする原寸比較では、キッチンの木の発色が改善する一方、集合写真の肌が赤くなり、庭と集合写真の平均色差が増加した。そのため一律の彩度追加を採用せず、元の共通変換の色合わせを再調整中。各候補を別ファイルへ保存し、v1や元画像は維持する。

アプリへの接続（更新版XMPのみ識別、追加調整、保存、Undo、旧方式への切替）はLuna / maxが実装済み。新しい適用helper等を含めた対象34テストとdebug buildが成功。最終色調整後にアプリbundleへ反映し、実UIで確認する。


### v2の再調整案

色の変換係数の制約を見直し、追加の一律彩度を使わず発色を合わせ直した。式と16knots / 23×3係数の構成は維持。選定は`color-balanced`（chroma ridge 0.000005、IRLS閾値0.15、5反復）。写真名や位置による処理分岐は使わない。

さらに、比較に含まれない極端に強い色で二次項の外挿が暴れないよう、色成分の大きさに応じて滑らかに中立曲線＋元の色方向へ移行する。`radius = sqrt(cr²+cb²)/(0.1+y)`が0.65〜1.1の間でsmoothstepし、完全移行時はneutral curve＋0.9×source chromaを使う。灰色の単調性と52,000色の有限性をRAW/JPEG各経路で確認する。これは別の写真への画質保証ではない。

再調整の試作では、RAWの平均ΔEがv1の7.75 / 4.33 / 4.65から、およそ6.63 / 2.88 / 2.78へ改善。原寸製品出力での値は実装後に再確認する。色のない領域を多く含む全体平均だけで採否を決めず、オーナーへ発色を再確認中。

Luna / maxへv2係数とガードの実装を委任。参照補正IDは`niho-bluesky2-reference-20260922-v2`とする。v1はユーザーへbundle配布しておらず、保存済み編集にも存在しないことを確認した。


### v2原寸・実UIと、木の発色に対する追加フィードバック

0.3.0/build3をrelease build・署名検証し、v2の原寸6出力を確認した。実UIでは更新版の自動追加（5登録）、4微調整、Undo/Redo、終了・再起動後の補正IDと微調整の復元、旧XMP切替とUndo復元を確認した。保存済みv2は自動で次版に置き換えず保持する。

オーナーから「さらに良くなったが、P1013558の奥の柱の木の色はLRの方が濃い（鮮やか）」と具体的な指摘を受けた。v2も最終受け入れ済みとは扱わない。

柱の診断ROI（3690,650–4000,1090、製品処理には使わない）では、RAWの彩度相当のLab chromaがLRの約0.91倍、Lab Lは約+2.69で、彩度不足と明るさの差が同時にあった。orange saturation+20/+30は過剰になったため不採用。既存のOKLCh mixerのorange帯だけ saturation+10、luminance−12、hue0をv2の後へ加える仕上げを選定した。その他の色帯は0。画像別の分岐やマスクは使用しない。

選定値の前後（luminance−10/−15）では、柱のRAW平均ΔEが2.96から1.43/1.30へ下がり、chroma比は1.00/0.99、Lab L差は+0.81/−0.06となった。JPEGも2.41から1.52/1.66へ改善。RAW/JPEGの両方を考慮した中間の−12を選ぶ。全6入力で同じorange調整を使う。

`niho-bluesky2-reference-20260922-v3`として実装し、既存v2のdecode/renderを保持、新しいプリセット選択だけv3へ切り替える。0.3.1/build4を予定。比較は`review-v3-wood.jpg`と`review-v3-full.jpg`。オーナーに仕上がりを再確認中。

選定値+10/−12の原寸試作で、柱ROIの平均ΔEはRAW 1.31、JPEG 1.51まで改善。一方、全画面の平均ΔEはv2より最大約0.22増えた。柱の見た目に関するオーナーの指摘を優先した調整であり、全画面の全指標が改善したとは表現しない。最終採否は3枚全体も含めたオーナー確認と実アプリ確認で決める。


### v3への再指摘と、局所コントラストの補正（v4作業中）

オーナーから「まだLRの方がくっきりしており、自作側は色がのっぺりしている。自分でも見比べてほしい」と指摘を受けた。v3も画質受け入れ済みとはしない。主担当が全体と柱・髪・顔の拡大を比較し、単純な平均彩度合わせでは局所的な陰影が不足すると判断した。更新版XMPにはTexture +12があるが、v3の画素単位色変換は空間的な明暗差を再現しない。

同じ色補正を維持したまま、全体contrast+20、局所補正、広い範囲を含む局所補正、混合案をRAW/JPEG全6経路で試した。全体contrastを上げる案は暗部を過剰に濃くするため不採用。広い範囲の補正が強い案も集合写真で強すぎるため、次を選んだ。

- v3の後、ユーザー追加調整の前に、sRGB encoded領域の輝度だけを局所補正する。処理間はfloatのCIImageでつなぎ、最後は従来のsRGB出力変換を使う。
- 長辺6000pxを基準にGaussian sigma 2 / 24 / 120px。画像寸法に比例させ、edge clampと元extentへのcropを行う。
- 輝度をy、3段のぼかしをyf/ym/ybとし、補正d = 0.4(y−yf)+0.5(yf−ym)+0.1(ym−yb)。d/(1+abs(d)/0.08)で急な境界の強調を抑える。暗部・極端な明部で滑らかに抑制する。
- 各encoded channelへ同じ輝度差を足し、linearへ戻す。alphaを維持し、平坦な色には補正しない。新たな一律彩度、写真固有の座標や分岐は追加しない。

診断画像は `exports/bluesky2-20260922/detail-probe/`、試作ソースと集計は `.photobench/bluesky2-20260922/probe-balanced.swift` / `detail-balanced-metrics.json`。位置合わせは診断集計だけに用い、製品出力は変形しない。v3の中程度の明暗差はLRの約0.81〜0.86倍だった。採用案は木目・髪・葉の陰影を近づける一方、集合写真の色・レンズ由来のフレアには差が残る。色差の平均だけで採用せず、主担当による視認結果を併記する。
